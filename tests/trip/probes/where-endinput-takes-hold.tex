% \endinput, and \input with no name at all.
%
% Measured against pdftex:
%
%   * \endinput ends the file after the LINE it stands on, not at itself.
%     `\message{[A]}\endinput\message{[B]}' prints both, and only the
%     lines below are lost. This engine dropped the rest of the line too.
%
%   * It takes hold the same way from inside a macro or a group.
%
%   * But `\input fj\endinput' does NOT end the file that wrote it, where
%     `\input fj \endinput' -- one space more -- does. \endinput is
%     EXPANDABLE, so without the space it takes hold while the file name is
%     still being scanned, and what it takes hold of is the file that name
%     is about to open: fj comes out ONE LINE LONG. With the space the name
%     has already ended, so the \endinput is read after fj has been read
%     out, and ends the file that wrote it. See the probe
%     what-an-endinput-in-a-file-name-ends. Any other terminator is read
%     again: `\input fj\message{[D]}' prints D.
%
%   * \input with no name -- `\input' at the end of a line, with only a
%     comment after it -- does nothing at all, in silence, and the file
%     carries on. This engine stopped.
%
% trip line 424 writes \expandafter\stopinput\input tripos\endinput\input
% with a comment after, which is all three of these at once.
\tracingonline=1
\message{[A]}\endinput\message{[B]}
\message{[never read]}
